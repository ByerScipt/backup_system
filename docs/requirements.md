## 1 引言

### 1.1 编写目的

本文档定义 Backup Studio 备份系统的功能需求、非功能需求、数据与接口需求，
作为设计、实现、测试与验收的共同依据。读者对象为课程指导教师、项目组成员
以及后续维护者。

### 1.2 适用范围

系统面向单机与可信局域网场景：把目录树打包成单一归档文件，还原时先校验后
提取；并可把归档上传到自建备份服务器，按账户隔离存储。系统同时提供命令行
（CLI）与 Qt 6 桌面端（GUI）两种操作方式。

### 1.3 术语与缩略语

| 术语 | 说明 |
| :--- | :--- |
| 归档（archive） | 单个 `.bak` 文件，形如 `BKP2` 头 + 编码负载 |
| packed 数据 | 打包阶段输出：条目元数据与文件数据 |
| encoded 负载 | 压缩与加密后的负载，位于归档头之后 |
| BKP2 | 自研归档容器格式，头长 112 字节，当前版本 3（1/2 仍可读） |
| NBKP | 自研网络协议（分帧 TCP），当前协议版本 1 |
| 挑战-响应登录 | 服务器下发随机挑战，客户端回证明，口令不落盘、不上线 |
| 硬链接 | 同一 inode 的多个目录项；版本 2 起的归档可保留其关系 |
| LZ77 压缩 | 以滑动窗口字典表示重复串的压缩；归档格式中压缩 id = 3，要求版本 ≥ 3 |
| 逐条提交 | 还原时每个条目独立创建并提交，不做整目录回滚 |
| CLI / GUI | `bin/backup-cli` 与 `bin/backup-gui` |

## 2 项目概述

### 2.1 背景与目标

课程要求实现一个具备归档、压缩、加密与网络传输能力的备份还原系统。
项目目标：

- 以统一归档格式保存目录树、权限、属主与时间戳，含符号链接、FIFO、
  字符/块设备与 Unix 套接字节点；
- 在不引入第三方压缩/加密库的前提下自研 RLE、Huffman、LZ77 压缩与
  ChaCha20、AES-256-CTR 加密；
- 还原过程默认安全：先完成全部校验再落地数据，路径解析受目标目录文件
  描述符约束，默认不覆盖既有文件；
- 提供账户隔离的远程备份服务，上传以声明大小与 SHA-256 校验后才提交；
- 命令行与桌面端复用同一套业务接口。

### 2.2 用户特征

| 角色 | 特征 | 主要入口 |
| :--- | :--- | :--- |
| 普通用户 | 需要备份个人/项目目录，可在本机或局域网内操作 | CLI 命令、GUI 页面 |
| 服务器管理员 | 部署并维护备份服务器、存储目录与端口配置 | `bin/backup-server`、`databackup.conf` |

### 2.3 运行环境

| 项 | 要求 |
| :--- | :--- |
| 操作系统 | Linux 为主要目标；Windows 通过 WSL2 构建与运行 |
| 编译器 | 支持 C++17 与 `std::filesystem` 的 GCC/Clang |
| 构建 | CMake 3.16+、`make`（Makefile 封装）；Qt 6 Widgets 可选 |
| 依赖 | 仅 C++17 标准库与 POSIX；无外部压缩/加密库 |
| 桌面端 | Qt 6 Widgets；缺省时 CMake 自动跳过并提示 |
| 发布部署 | CLI、服务端与一体包均提供 Ubuntu 24.04 的 deb 与 tar.gz；服务端另提供 systemd 单元与容器镜像；Windows 经 WSL2 安装脚本使用 |

### 2.4 假设与约束

1. 网络协议**不含 TLS**，仅可用于可信网络；归档机密性由归档加密单独保证。
2. 属主、权限与时间戳还原需要相应 OS 权限；无权限时必须上报失败，不得静默忽略。
3. 归档输出必须位于源目录之外且路径不存在；还原默认不覆盖。
4. `ctime` 只能记录不能还原；`btime`、ACL、扩展属性不在支持范围内。
5. 取消操作不回滚已提交的归档或已还原的条目。

## 3 功能需求

### 3.1 功能清单

| 编号 | 功能 | 对应操作 | 说明 |
| :--- | :--- | :--- | :--- |
| FR-01 | 本地备份 | `backup-cli backup SOURCE -o ARCHIVE` | 打包目录树为单一归档，支持 `--pack`、`--compress`、`--encrypt` |
| FR-02 | 本地还原 | `backup-cli restore ARCHIVE -d DEST` | 校验通过后还原到 `DEST/<源目录名>` |
| FR-03 | 覆盖控制 | `--overwrite` | 缺省拒绝与既有路径冲突；显式开启后覆盖 |
| FR-04 | 归档检视 | `backup-cli inspect ARCHIVE` | 输出头信息并校验负载摘要，不需要口令 |
| FR-05 | 冲突预览 | GUI 本地还原页 | 提取前列出条目与冲突路径，不占用目标路径 |
| FR-06 | 账户注册 | `backup-cli user register` | 客户端生成盐与校验值，服务器不保存明文口令 |
| FR-07 | 账户登录 | `login` / 各远程命令隐式登录 | 挑战-响应证明；每次传输独立认证 |
| FR-08 | 远程上传 | `backup-cli remote-backup SOURCE` | 先本地归档，再上传；返回备份 ID |
| FR-09 | 远程列表 | `backup-cli remote-list` | 只列出当前账户的备份（名称、ID、时间、大小、摘要） |
| FR-10 | 远程还原 | `backup-cli remote-restore BACKUP_ID -d DEST` | 先下载到本地，再按 FR-02 还原 |
| FR-11 | 注销账户 | GUI「注销账户」 | 仅当账户无已存备份且无其他已认证连接时允许 |
| FR-12 | 服务器运行 | `backup-server [--config|--bind|--port|--storage|--max-connections]` | 监听（含回环）、限流、存储与账户管理 |
| FR-13 | 进度与取消 | `ProgressCallback` / GUI 任务区 | 各阶段上报进度，可取消；取消不提交最终产物 |
| FR-14 | 算法组合 | `--pack stream|index`、`--compress none|rle|huffman|lz77`、`--encrypt none|chacha20|aes256` | 共 2×4×3 组合 |
| FR-15 | 元数据保留 | 备份与还原全过程 | 权限、属主、atime/mtime、符号链接、设备号、硬链接 |
| FR-16 | 账户隔离存储 | 服务器存储根目录 | 每账户独立目录，权限 0700，文件名不可预测 |

### 3.2 关键用例

#### UC-01 本地备份

- 参与者：用户
- 前置条件：源目录存在且可读；输出路径位于源目录之外且不存在。
- 主流程：
  1. 用户提交源目录、输出路径与算法选项（可含口令文件）。
  2. 系统校验选项与路径（输出不得位于源目录内，不得已存在）。
  3. 扫描目录树，收集条目元数据与硬链接关系，统计输入字节数。
  4. 打包为 packed 暂存件（`stream` 顺序式或 `index` 索引式）。
  5. 按需压缩（`none`、`rle`、`huffman`、`lz77`）。
  6. 按需加密（随机 16 字节盐；ChaCha20 或 AES-256-CTR）。
  7. 写入 112 字节 `BKP2` 头（含 packed/encoded 摘要与大小），`fsync`
     后原子提交为最终归档。
  8. 返回条目数、输入/输出字节数。
- 异常流：口令缺失、源不可读、磁盘写满、取消、输出冲突、`fsync` 失败
  （报错并说明归档已发布）。
- 后置条件：归档文件存在且自校验一致；中间暂存件全部清理。

#### UC-02 本地还原

- 参与者：用户
- 前置条件：归档存在；加密归档需同一口令；目标目录可写。
- 主流程：
  1. 读取头并校验 `encoded` 负载 SHA-256。
  2. 解密、解压到暂存件，校验 `packed` 摘要与大小。
  3. 解析条目：路径安全（不含绝对路径、`.`、`..`、NUL）、路径唯一、
     数据边界不越界、硬链接目标已存在。
  4. 打开目标目录 FD（`O_DIRECTORY|O_NOFOLLOW`），按深度先建目录。
  5. 逐条创建临时节点 → 写入数据 → 应用元数据 → 提交（默认不覆盖）。
  6. 反序写回目录元数据，返回结果。
- 异常流：口令错误、归档损坏/截断、解压越界、路径逃逸、目标竞态替换、
  元数据设置失败（必须上报，已还原条目保留）。
- 后置条件：冲突在未开启 `--overwrite` 时被拒绝；失败信息可定位到条目。

#### UC-03 远程上传

- 参与者：用户、备份服务器
- 前置条件：服务器可达；账户已注册。
- 主流程：
  1. 客户端按 UC-01 生成本地归档并计算大小与 SHA-256。
  2. 建立 TCP 连接，`LoginStart` → `LoginChallenge(salt, nonce)` →
     `LoginProof = SHA256(verifier ∥ nonce)` → `LoginResponse`。
  3. `UploadStart(displayName, size, sha256)`；服务器返回 `UploadReady(id)`。
  4. 以 512 KiB 分帧发送 `UploadChunk`，最后发送 `UploadEnd`。
  5. 服务器校验大小与 SHA-256，原子提交到账户目录并写元数据。
  6. 返回 `UploadResult(id)`；客户端仅在该确认后对外暴露备份 ID。
- 异常流：认证失败、超限、连接中断、取消、摘要不一致（暂存件不提交）。

#### UC-04 远程还原

- 参与者：用户、备份服务器
- 主流程：登录 → `DownloadRequest(id)` → `DownloadStart/Chunk/End`
  （服务器先校验存储摘要）→ 客户端下载到临时文件 → 按 UC-02 还原。
- 异常流：备份不属于该账户、存储摘要不匹配、下载中断、取消。

#### UC-05 账户管理

- 主流程：注册（盐+校验值上传）、登录、注销（要求无备份且无并发会话）。
- 约束：用户名 1–64 字符；口令不落盘；注销不可撤销已提交的删除。

#### UC-06 服务器运维

- 主流程：读取 `databackup.conf` 或命令行覆盖监听地址、端口、存储目录、最大连接数、
  超时；就绪后监听；`SIGINT`/`SIGTERM` 触发优雅停机并传播取消。
- 约束：非法/未知配置项与非法数值（含非 IPv4 字面量的 `bind_address`）必须拒绝启动；
  存储相对路径相对进程工作目录解析。

## 4 非功能需求

| 编号 | 类别 | 需求 |
| :--- | :--- | :--- |
| NFR-01 | 性能 | 160 MiB 输入在 128 MiB 虚拟内存上限下完成备份与还原；单进程峰值 RSS 可控（见测试报告实测值） |
| NFR-02 | 可靠性 | 负载与 packed 数据双重 SHA-256；归档发布与服务器提交均为「临时文件 + 原子重命名」 |
| NFR-03 | 安全性 | 还原路径解析受目录 FD 约束；`O_NOFOLLOW`/`AT_SYMLINK_NOFOLLOW` 逐层防护；拒绝路径逃逸与竞态替换；账户口令以挑战-响应方式认证 |
| NFR-04 | 数据完整性 | 上传按声明大小与摘要校验后才提交；损坏、截断、越界归档必须拒绝 |
| NFR-05 | 可移植性 | 平台差异用条件编译局部隔离，不得改变 POSIX 平台行为；仅使用 C++17 与 POSIX |
| NFR-06 | 可维护性 | 公共接口集中在 `libs/`；命名 `snake_case`/`PascalCase`/`camelCase`；clang-format 18、80 列、Allman 风格 |
| NFR-07 | 可用性 | GUI 中文界面、进度与日志、可取消、关闭窗口取消全部任务并等待清理 |
| NFR-08 | 可测试性 | 全部核心/网络/CLI/GUI 行为可由 CTest 离屏执行；文件系统用例使用临时目录，网络用例使用本机临时端口 |
| NFR-09 | 可诊断性 | 失败必须返回可定位原因；不得把「不存在」「空集合」与错误混为一谈 |
| NFR-10 | 资源管理 | 文件句柄与临时文件 RAII 管理；取消与异常路径不得泄漏描述符或残留暂存件 |

## 5 数据需求

### 5.1 归档文件（BKP2）

| 组成 | 说明 |
| :--- | :--- |
| 头 | 112 字节：魔数 `BKP2`、版本（1/2/3）、头长、标志、算法 id、packed/encoded 大小、16 字节盐、两个 32 字节 SHA-256 |
| packed 数据 | `stream`：8 字节魔数 + 条目数 + 逐条（标记、元数据、数据）；`index`：8 字节魔数 + 文件数据区 + 中央目录 + 32 字节尾部 |
| encoded 负载 | packed 数据经压缩、加密后的字节流，长度记为 `encodedSize` |

条目元数据字段：路径、类型（普通/目录/符号链接/FIFO/字符设备/块设备/
套接字/硬链接）、权限位、属主、属组、大小、atime/mtime/ctime（秒+纳秒）、
链接目标、设备号；索引式附加内容偏移。

### 5.2 服务器存储

```
<storage_path>/                 # 缺省 ./server_data
  ├── users.dat                 # 账户库：用户名 + 16B 盐 + 32B 校验值
  └── <username>/               # 0700，每账户独立
        ├── <id>.bak            # 上传归档（0600）
        └── <id>.meta           # 展示名、时间戳、大小、SHA-256
```

### 5.3 配置文件（`databackup.conf`）

| 段/键 | 类型 | 缺省 | 约束 |
| :--- | :--- | :--- | :--- |
| `[server] port` | 整数 | 8848 | 1–65535 |
| `[server] bind_address` | IPv4 字面量 | `0.0.0.0` | 仅接受 IPv4 字面量；一体包经 systemd drop-in 用 `127.0.0.1` |
| `[server] storage_path` | 路径 | `./server_data` | 非空；相对路径相对进程工作目录 |
| `[server] max_connections` | 整数 | 32 | 1–1024 |
| `[server] timeout_seconds` | 整数 | 30 | 套接字读写超时 |

## 6 接口需求

### 6.1 命令行接口

| 命令 | 位置参数 | 允许选项 | 缺省 |
| :--- | :--- | :--- | :--- |
| `backup` | `SOURCE` | `-o ARCHIVE`、`--pack`、`--compress`、`--encrypt`、`--key-file` | `stream`/`none`/`none` |
| `restore` | `ARCHIVE` | `-d DEST`、`--key-file`、`--overwrite` | 不覆盖 |
| `inspect` | `ARCHIVE` | — | — |
| `user register` | — | `--server`、`--username`、`--account-password-file` | 交互输入口令 |
| `remote-backup` | `SOURCE` | 远程与本地算法选项、`--name` | 显示名缺省为备份 ID |
| `remote-list` | — | `--server`、`--username`、`--account-password-file` | — |
| `remote-restore` | `BACKUP_ID` | `-d DEST`、远程与本地选项、`--overwrite` | 不覆盖 |

约束：命令只接受自身允许的选项；重复选项、非法数值（如 `0`、`65537`、
`+80`、`80junk`、前导/尾随空格）必须拒绝；`--help`/`--version` 可用。

### 6.2 桌面端接口（GUI）

| 页面 | 功能 | 关键交互 |
| :--- | :--- | :--- |
| 起始页 | 登录 / 注册 / 账户信息 / 切换与注销 | 口令不回显；注销需二次确认 |
| 本地备份 | 源目录、输出归档、算法与口令 | 目录选择、进度、日志、取消 |
| 本地还原 | 归档、目标目录、覆盖选项 | 冲突预览、覆盖二次确认 |
| 远程备份 | 连接信息、归档算法、显示名 | 上传进度、备份 ID 展示与复制 |
| 远程还原 | 连接信息、备份 ID、目标目录 | 下载进度、还原进度 |
| 备份历史 | 列表、搜索、排序、复制 ID、转还原 | 名称/ID 搜索、大小排序、整 ID 复制 |

共享约束：账户与连接字段在内存中共享、不落盘；窗口关闭时取消全部活动任务并
等待清理；日志默认折叠但不丢弃输出。

### 6.3 网络协议接口（NBKP v1）

- 帧格式：16 字节头（`NBKP` 魔数、版本、消息类型、请求 ID、负载长度）+
  负载，单帧负载上限 1 MiB。
- 消息族：注册（1/2）、登录（3–6）、上传（10–14）、列表（20/21）、
  下载（30–33）、注销（40/41）、错误（255）。
- 认证：`LoginProof = SHA256(SHA256^4096(口令 ∥ 盐) ∥ nonce)`；服务器只保存
  盐与校验值；口令错误与用户不存在均返回同一错误文本。
- 传输：上传分块 512 KiB；下载同样分块；响应请求 ID 必须与请求一致。
- 超时：连接/读写等待 30 秒（可配置）并轮询取消；DNS 解析仍受系统解析器
  超时约束。

## 7 验收标准

| 验收项 | 判定标准 |
